当前状态：后台填表/下单尚未验收通过。已经发布的后台适配器仍只允许查询；本次交易探测只改了被忽略的临时脚本，没有把下单能力接进发布包。

## 已被否定的结论

“附着线程输入 + SetFocus 不会抢前台”不成立。“字段截图出现股票代码”只能证明某个时刻写入了文字，不能证明整个操作、异步弹窗及退出期间用户桌面不受影响。

演示日志明确显示：

| 阶段 | 当前桌面 | 前台 | 结论 |
| --- | --- | --- | --- |
| 定位表单 | 工作桌面 | 工作窗口 | 尚未发现干扰 |
| 填写代码后（约 5.688 秒） | 测试桌面 | 下单窗口 | 已失败，应立即中止 |
| 后续价格/数量填写 | 测试桌面 | 下单进程窗口 | 脚本错误地继续操作 |

原临时脚本的监测只追加到 `leaks` 列表，没有把它作为终止条件。清理时还先停掉监测，再把仍可见的下单窗口搬回工作桌面，最后才隐藏，因此退出阶段也可能露出窗口。

本次已禁用八个相关临时实机脚本。没有再次操作客户端，也没有下单。

## API 边界

微软的 [AttachThreadInput 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-attachthreadinput) 明确说明，该调用共享键盘状态和当前焦点；附着后键状态还会重置。它不提供独立输入环境。

[SetFocus 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setfocus) 明确说明，该调用也会激活获得焦点的窗口或其父窗口。因而不能承诺它只改变“线程内焦点”而不产生全局可见影响。

任务视图桌面用于分组窗口，不是独立输入桌面。单次 `cloaked=2` 或操作前后的同一前台句柄，都不能证明期间没有跳屏。

桌面上命中测试读到另一个软件的 Chromium 窗口，只能说明该软件遮挡了坐标，不能据此推断同花顺的交易表单改成了网页。读取不到文字也不证明控件一定有防自动化加固。这些此前的推断均没有充分证据。

## 已做的离线修正

正式只读模式增加以下检查（尚未重新进行实机回归）：

- 干扰一旦观察到，就在该次操作中锁存；即使桌面随后跳回来，也不能恢复为成功。
- 客户端窗口可见但未被遮蔽时，即使前台进程不变，也按失败处理。
- 检查行情窗口是否仍属于后台桌面。
- 发现干扰后，后续提交、刷新与输入不得继续；只释放本次拥有的保护，不通过点击或搬回窗口“修复”现场。

这些是失败保护，不是对所有激活行为的拦截，离线通过不代表后台下单已经解决。

## 本轮新增证据

在自建非输入桌面上，用一个会拒绝外部直接写入、且只在自身获得焦点时接受字符的合成表单验证受限通道：

| 场景 | 结果 |
| --- | --- |
| 表单预先处于活动状态 | 三字段精确写入/读回/清空，非法控件被拒；原活动窗口与焦点复原 |
| 表单无活动窗口（复现客户端状态） | 字段写入成功，但无法把“无活动窗口”恢复回去，用例失败 |

两者都没有共享输入队列、没有安装全局键鼠钩子、没有切换用户输入桌面，宿主退出后已卸载。

客户端只读探测：目标线程当前 `active` 与 `focus` 均为空，窗口在另一任务视图桌面并被遮蔽。用禁用字段写入的探测版本对该线程执行同样的局部状态准备，返回恢复错误；之后客户端自行回到原状态，`active` 变回空且窗口隐藏。这只说明该恢复假设不成立，不能据此认为客户端被破坏，其可见性与进程身份检查仍正常。

关键限制：Windows 没有公开接口把线程的活动窗口设回“无”。任何需要临时激活窗口的写入路径，在客户端原本没有活动窗口时都会留下一个可观测的状态改变，因此不满足“不打扰”要求。真实客户端的字段写入、价格数量填写与提交均未执行。

## 后续实施约束

后续实验统一复用项目的线程激活保护和守卫，不再绕过它们另写一套直接操作实盘的演示程序。

1. 先在自建窗口上验证整个输入及弹窗流程；不使用真实资金表单作为第一轮调试对象。
2. 不再把共享输入队列的 `AttachThreadInput` 当作免打扰保证。需要验证客户端 GUI 线程内的受限操作通道，并由已授权的线程激活保护约束它；其可行性尚未确认。
3. 字段动作前后以及等待异步响应时都检查守卫。观察到任何一次泄漏，该轮失败，禁止继续、重试或自动提交。
4. 监测覆盖初始化、字段输入、确认弹窗、异步响应及结束阶段；默认让客户端留在后台，不能先把可见窗口搬回来再隐藏。
5. 实机验收先只填表，不提交；完整交易还必须验证委托编号、拒单原因和状态查询。拿到表单截图不算下单通过。

## 原有功能范围

用户要求的是现有 ClientTrader 功能的后台对应实现，范围以实际代码为准：限价买卖、市价买卖、可撤委托查询、单笔/全部撤单、批量新股申购、正回购和逆回购。`repo` 是正回购，不能与 `reverse_repo` 混称为逆回购。

菜单中出现“条件单”或“止盈止损”按钮，不足以证明它是券商服务器托管功能；它们也不是现有 ClientTrader 的完整公开实现，不能把仅发现按钮列为已实现。

本次没有验收真实委托，没有选择股票、数量或价格执行买卖，也没有发布新包。

## 结论

该方案验证未通过，不建议继续沿此路推进后台交易录入。

- 合成表单在“无活动窗口”初始状态下，字段写入成功但退出状态无法还原，用例判定失败。
- 同条件下对真实客户端只做无字段的状态准备，同样返回恢复错误。
- 正式发布包仍为只读，交易方法全部抛 `PermissionError`。

## 现场状态

- 隔离实验无残留进程，用户输入桌面仍为 `Default`。
- 已清理一个实验遗留的空任务视图桌面；承载客户端的后台桌面保留。
