# 同花顺隐藏窗口只读查询

同花顺平时留在当前工作桌面并隐藏主窗口。资金、持仓、当日委托、当日成交通过定向控件消息读取；触发查询验证码时，允许验证码窗口临时显示并取得焦点，输入和确认后收起并归还焦点。

不再创建、移动、切换或管理任务视图桌面，不需要 pyvda、AutoHotkey 或另开同花顺实例。后台账户对象仍然只读，不提供买卖、撤单、登录、打新或回购能力。

## 使用

```python
import easytrader

with easytrader.use("ths", background=True) as user:
    user.connect()  # 连接现有已登录的同花顺远航版
    print(user.balance)
    print(user.position)
    print(user.today_entrusts)
    print(user.today_trades)
```

默认允许查询验证码临时占前台。此时请等待验证码输入结束，不要同时向验证码框打字。普通查询不发送全局键鼠输入；验证码输入前会核对前台窗口、输入焦点、PID 和控件身份，确认失败即停止。

如果某个调用不允许前台输入，可显式设置：

```python
user = easytrader.use("ths", background=True, allow_foreground_captcha=False)
```

该选项保证不向验证码输入键盘字符；如果客户端自行弹出验证码，该次查询失败并取消自身创建的查询验证码。它不保证客户端不会短暂显示验证码，因此不是“全程无弹窗”模式。

`close()` 默认停止查询工作线程并让主窗口保持隐藏。需要手动查看客户端时，在关闭工作线程前显式调用 `user.restore_windows()`；该方法仅恢复窗口可见性，不搬动任何桌面。也可使用 `restore_on_close=True` 主动要求退出时显示原本可见的主窗口。

## 查询与验证码流程

1. 连接时校验唯一行情/下单窗口、进程路径、归属及菜单树，然后隐藏主窗口。
2. 查询按菜单实际选中项发送 `TVM_SELECTITEM`；表格复制使用 `WM_COMMAND 0xE122`，不使用 F5 或鼠标点击。
3. 普通查询阶段使用单一 GUI 线程的临时激活拦截；发现主窗口或未知弹窗显示、进程身份变化、用户锁屏等情况时锁存失败并中止。
4. 只在本次复制产生的验证码上释放激活拦截，内存截图后用随包 ONNX 模型识别。输入前验证前台和焦点，先退格清空、等待，再逐字符输入；“确定”按钮使用定向消息。
5. 以新剪贴板序号、属主 PID 和所需表头共同验证查询结果；关闭验证码并不等同于已获得数据。
6. 成功、失败和超时都收起主窗口；只有客户端仍占前台时才尝试归还查询前的工作窗口。用户已切换到其他应用时不抢回。

既有查询验证码或未知弹窗不会被当成新请求的弹窗自动确认。失败只取消本次已识别、身份仍匹配的查询验证码，不处理交易确认框。

## 实机验证范围

本次只读验收在主窗口隐藏且没有任务视图 API 调用的情况下完成：

| 查询 | 结果 | 验证码次数 | 用时 |
| --- | --- | --- | --- |
| 资金 | 5 项字段 | 0 | 约 0.55 秒 |
| 持仓 | 空表 | 1 | 约 2.94 秒 |
| 当日委托 | 16 条记录 | 1 | 约 2.17 秒 |
| 当日成交 | 空表 | 1 | 约 2.17 秒 |

该轮三个验证码均首次通过。20ms 轮询监测未发现主窗口显示或未知客户端弹窗；查询结束时主窗口仍隐藏、无残留验证码，前台恢复为原工作窗口。轮询不是对任意短暂显示的数学证明，这些结果也不能外推到客户端升级后的行为。

非空持仓/成交、长期无人值守、多实例、非 x86 下单窗口仍未验收。此次没有提交、确认或撤销任何交易委托。验证码模型推理耗时和整个查询耗时是不同指标，不能用单张推理时间代替输入、提交、换图及券商响应时间。

## 安装与测试

```powershell
python -m pip install -e .
python -m pytest tests/ -q
```

`.[background]` 仍作为兼容的空 extra 接受，不再安装 pyvda。ONNX 模型随包提供；同花顺查询验证码不调用 Tesseract，其他历史券商识别入口仍可能使用它。

原任务视图后台方案和独立 Win32 桌面面板已移除。关于它们的历史验证失误，可查阅 `background-trading-review.md`；该记录不描述当前实现。
